# Скорость и нагрузка (раунд 10, 18.11.2026)

Замеры на production-сборке (`npm run build`, `output: standalone`) на одной машине: 2 ядра, 7 ГБ памяти, PostgreSQL 16 на той же машине. Демо-данные — как у жюри: 11 студентов (3 демо-аккаунта с полными данными), ~500 занятий, ~90 заявок, ~300 уведомлений. Запросы к базе фильтруются по студенту и индексам, поэтому время страницы почти не зависит от общего числа студентов. На живом сайте нагрузку не запускали — там идёт проверка.

## Нагрузка
Скрипт: `scripts/load-test.mjs` (autocannon, MIT; 20 секунд на каждую строку; запросы от вошедшего студента).

| Страница | Одновременных запросов | Ответов в секунду | Медиана | 97,5 % ответов быстрее | Ошибок |
|---|---|---|---|---|---|
| Сегодня `/` | 10 | 47 | 206 мс | 289 мс | 0 |
| Сегодня `/` | 50 | 51 | 962 мс | 1147 мс | 0 |
| Расписание | 10 | 69 | 141 мс | 200 мс | 0 |
| Успеваемость | 10 | 46 | 212 мс | 311 мс | 0 |
| Заявки | 10 | 73 | 133 мс | 177 мс | 0 |
| Вход (страница) | 50 | 135 | 347 мс | 560 мс | 0 |

**Как читать.** Одна копия приложения на 2 ядрах отдаёт ~50–70 полностью собранных страниц кабинета в секунду. Студент открывает страницу примерно раз в 5–10 секунд, значит одна копия выдерживает ~250–700 студентов, которые *прямо сейчас* активно кликают, без единой ошибки. При перегрузке (50 одновременных запросов) ответы замедляются до ~1 с, но не падают.

**Что дальше при росте.** Приложение не хранит состояние в памяти: сессии, лимиты попыток и блокировки — в PostgreSQL. Поэтому копии можно добавлять горизонтально за балансировщиком; узкое место следующего порядка — база (решение — пул соединений и реплика для чтения расписания; см. `docs/ARCHITECTURE.md`, раздел «Масштабирование»).

### Что исправили по результатам
| Было | Причина | Исправление |
|---|---|---|
| На всех страницах кабинета «крупнейший элемент» (LCP) ≈ 4 с — окно подсказок | Флаг «подсказки пройдены» проверялся только в браузере после загрузки, окно рисовалось последним | Сервер читает cookie флага и не отдаёт задачу показа (`(student)/layout.tsx`) |
| Страница входа «прыгала» при загрузке шрифтов (CLS 0,13) | Системный шрифт-заменитель шире и выше Golos / PT Serif | Заменитель подогнан по метрикам: `size-adjust`, `ascent/descent-override` (посчитаны fontTools по файлам шрифтов) |
| 8 файлов шрифта Golos (4 начертания × 2 алфавита) | Статические начертания | Вариативный Golos — 2 файла, на 22 КБ меньше |
| Значок сайта не показывался на странице входа (и на живом сайте) | Запрос `/icon.svg` без входа перенаправлялся на `/login` | Значки исключены из проверки входа в `src/proxy.ts`; e2e-тест |

### Почему на телефоне не 95+
Остаток — базовый JavaScript Next.js и React (~115 КБ в сжатом виде), который скачивается до первой отрисовки на медленном 4G. Убрать его можно только сменой фреймворка; на реальном 4G/Wi-Fi и на компьютере страницы открываются за 0,7–1 с.
