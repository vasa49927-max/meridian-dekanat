## Безопасность (критерий 3 — проверяется жюри руками)
- Пароли — argon2id или bcrypt; в БД только хэши.
- Сессии — httpOnly + Secure + SameSite cookie, серверная проверка на каждом запросе; logout инвалидирует сессию.
- Авторизация на уровне данных: любой запрос к профилю, оценкам, заявкам, уведомлениям фильтруется по userId из сессии, а не по id из URL. Подмена id в адресе или в API-запросе → 404. Роли student / staff, проверка роли на сервере.
- Rate limiting и защита от перебора на входе; понятные, но не раскрывающие лишнего ошибки.
- Заголовки безопасности (CSP, X-Frame-Options и др.), проверка Origin для изменяющих запросов.
- Все секреты (БД, ключ ИИ, секрет сессий) — только в переменных окружения; .env в .gitignore, в репо — .env.example. Ни одного ключа в клиентском бандле — проверь это поиском по сборке.
- Напиши e2e-тесты на изоляцию данных: студент A не может открыть профиль/заявку/оценки студента B ни через UI, ни через API.

## Продукт
### Обязательное ядро — сделать полностью и связно
1. Вход и профиль: ФИО, факультет, направление, курс, группа, фото-аватар (сгенерированный/иллюстрация), номер зачётки (вымышленный).
2. Расписание: «сегодня» и «неделя», аудитория, корпус, преподаватель, тип занятия; изменения и переносы заметно подсвечены и дублируются в уведомления; экспорт в календарь (.ics).
3. Успеваемость: дисциплины, баллы по балльно-рейтинговой системе, зачёты/экзамены, сессия; понятная сводка «как у меня дела» (средний балл, риски, что нужно, чтобы получить «автомат»/нужную оценку).
4. Заявки и справки: каталог справок и заявлений, форма за 1–2 экрана, статус-трекер (подана → в работе → готова → выдана / отклонена с причиной), история заявок; готовая справка — электронная, с QR-кодом проверки подлинности.
5. Уведомления: лента новостей и объявлений деканата, напоминания о дедлайнах и изменениях, фильтры, прочитано/не прочитано, счётчик.

### Кабинет сотрудника деканата (обязательно для связности сценариев)
Очередь заявок с фильтрами → смена статуса с комментарием → студент сразу видит новый статус и получает уведомление. Публикация объявлений (всем / курсу / группе). Внесение переноса пары → уведомление затронутым группам. Это даёт жюри пройти полный цикл «студент подал → деканат обработал → студент увидел».

### Смелые идеи (выбери 3–4 и сделай их качественно, а не 10 наполовину)
- Главный экран «Сегодня»: следующая пара с обратным отсчётом, ближайшие дедлайны, статус заявок, важные объявления — всё нужное за одно касание.
- ИИ-помощник деканата: отвечает на вопросы по (вымышленному) положению о деканате и данным самого студента («какую справку взять для военкомата?», «что у меня с сессией?»), умеет сам заполнить заявку. Только через серверный маршрут, ключ в env; если ключа нет — аккуратное отключённое состояние.
- Глобальный поиск / командная палитра по всем разделам.
- Электронная запись к методисту вместо живой очереди.
- Кампус-навигатор по аудиториям, клубы и мероприятия (студсовет, бизнес-клуб), тёмная тема.
Предложи свои идеи в духе «каким деканат может стать», особенно специфичные для МГИМО.

### Качество (критерий 4)
Цельная дизайн-система (токены цвета, типографика, отступы — docs/DESIGN.md), светлая и тёмная темы. Мобильная навигация снизу (tab bar), десктоп — сайдбар. Все сценарии работают на 360 px без горизонтального скролла. Продуманы пустые состояния, ошибки, скелетоны загрузки, офлайн-состояние. Доступность: контраст AA, фокус, aria, работа с клавиатуры. Быстро: цель Lighthouse ≥ 90 по Performance и Accessibility на мобильном — замерь и приложи цифры.

### Данные
Seed-скрипт с правдоподобными вымышленными данными на текущий семестр (осень 2026): минимум 3 студента с разными факультетами/курсами/группами/оценками/заявками, 1 сотрудник деканата, 10+ преподавателей, расписание на несколько недель с переносами.
