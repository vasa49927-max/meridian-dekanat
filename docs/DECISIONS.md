# Журнал решений (ADR-lite)

Формат: **D-NNN — решение** · кто решил · почему · альтернативы.
«Капитан» — решение Родиона; «ИИ» — решение Claude по умолчанию (Родион может пересмотреть).

### D-001 — Хостинг: Amvera · Капитан (06.11)
Российский PaaS: деплой из Dockerfile по git push/вебхуку GitHub, managed PostgreSQL (CloudNativePG) в том же кабинете, HTTPS-домен, оплата в рублях.
Тарифы (docs.amvera.ru/general/price.html, 06.11.2026): приложение «Начальный Плюс» 0,5 CPU / 1 ГБ — 490 ₽/30 дн; PostgreSQL «Начальный» 0,25 CPU / 500 МБ — 290 ₽/30 дн. Посекундная оплата → до 28.11 ≈ 600 ₽.
Альтернативы: Timeweb Cloud (дороже, больше ручной настройки), Yandex Cloud (грант, но сложная настройка IAM/сетей/реестра). Отклонены: Vercel/Netlify/Render — нестабильно открываются в РФ без VPN.

### D-002 — ИИ-помощник в кабинете: GigaChat API · Капитан (06.11)
Ключ — только в переменной окружения сервера. Вызов — только из route handler `/api/assistant`. Нет ключа → помощник показывает аккуратное «выключено» и работает в режиме поиска по положению без LLM.

### D-005 — Стек: Next.js 16 (App Router) + TS + Tailwind v4 + shadcn/ui + Prisma 7 + PostgreSQL 16 · ИИ (06.11)
Совпадает с дефолтом ТЗ команды. Один язык (TS) на фронте и бэке — ИИ-агентам проще держать контекст; Server Components уменьшают JS на клиенте (Lighthouse). Prisma 7 — стабильная ветка (8.x на 06.11 ещё RC), работает через драйвер `pg` без бинарного движка → меньше образ.
Масштабирование: сервер без состояния (сессии и лимиты попыток — в БД), можно поднять N реплик за балансировщиком; индексы на всех внешних ключах и полях фильтрации; курсорная пагинация лент.

### D-006 — Собственные сессии вместо NextAuth/Auth.js · ИИ (06.11)
Нужен только вход по логину/паролю. Своя реализация — ~150 строк, полностью прозрачна для жюри и аудитора: токен 32 байта → в cookie, SHA-256 → в БД, срок 7 дней со скользящим продлением, logout удаляет запись. Меньше «магии» и зависимостей.

### D-007 — argon2id через `@node-rs/argon2` · ИИ (06.11)
Предсобранные бинарники (без node-gyp) → надёжная сборка в Docker на Amvera. Параметры OWASP: m=19 МиБ, t=2, p=1.

### D-008 — Локальная БД без Docker · ИИ (06.11)
В песочнице разработки Docker-демон недоступен → PostgreSQL 16 запускается бинарниками (`scripts/pg-local.sh`). Для других разработчиков в репо остаётся `docker-compose.yml`.

### D-009 — Шрифты self-host через `@fontsource` · ИИ (06.11)
`next/font/google` скачивает шрифт с Google во время сборки — на билд-серверах в РФ это риск. `@fontsource` берёт файлы из npm, лицензия OFL.

### D-010 — Дизайн-направление A «Посольство» · Капитан (КТ (а), 06.11)
Из трёх вариантов (A «Посольство», B «Кампус», C «Ночная библиотека») выбран A. Тёмная тема сделана в его палитре (глубокий синий + латунь).

### D-011 — Название «Меридиан» · Капитан (КТ (а), 06.11)
Логотип — дуги меридианов и звезда-ориентир (идея международности, без копирования эмблемы вуза).

### D-012 — Смелые идеи: ИИ-помощник, «что, если» по БРС, запись к методисту, командная палитра · Капитан (КТ (а))
Плюс поддерживающие: главный экран «Сегодня», статус «нужно дополнить» как в Госуслугах, справки с QR, языковой паспорт в профиле, день ВУЦ в расписании, PWA, тёмная тема.

### D-013 — `cacheComponents` выключен · ИИ (06.11)
Next 16 по умолчанию включает Cache Components. Кабинет полностью персональный: динамический рендер всех страниц исключает риск отдать закешированные данные одного студента другому. Производительность компенсирована серверными компонентами и ленивой загрузкой палитры.

### D-014 — Drizzle ORM вместо Prisma · ИИ (06.11), отклонение от дефолта ТЗ
Prisma 7 при `migrate` скачивает бинарный schema-engine с binaries.prisma.sh — домен закрыт в песочнице разработки (403). Drizzle — чистый TypeScript, миграции — обычные SQL-файлы в `drizzle/`, нет бинарников → меньше образ и предсказуемая сборка на Amvera. Лицензия Apache-2.0.

### D-015 — Миграции и первичный сид при старте сервера · ИИ (07.11)
`src/instrumentation.ts` → `runStartup()`: применяет миграции, при пустой БД создаёт демо-данные. Родион не запускает команды вручную на хостинге.

### D-016 — Демо-данные «относительно сегодня» и «созревающие» уведомления · ИИ (06.11)
Переносы на ближайшие 10 дней объявлены к моменту сида, дальше — появляются по времени (`created_at ≤ сейчас`). Кабинет остаётся «живым» все три недели проверки без пересоздания.

### D-017 — Офлайн без кэширования личных страниц · ИИ (07.11)
Service worker кэширует только статику и экран `/offline`. Первоначально ИИ кэшировал «Сегодня/Расписание/Успеваемость», но это риск на общем компьютере — убрано.

### D-018 — ИИ-помощник без права действия · ИИ (07.11)
Модель только предлагает «Заполнить заявку» (ссылка на форму с проверенными полями); отправляет студент. Без ключа или при ошибке GigaChat — офлайн-режим: поиск по Положению (TF-IDF) + правила для частых вопросов.

### D-019 — Rate limiting: «логин+IP» / логин / IP, IP от доверенного прокси · ИИ по отчёту аудитора (07.11)
См. находки M-1, M-3 в `PROCESS_LOG.md`, этап 10.

### D-020 — Сертификаты НУЦ Минцифры из `certs/`, без отключения TLS · ИИ (07.11)
Официальный README пакета gigachat предлагает `rejectUnauthorized: false` — отказались. Сначала план был `NODE_EXTRA_CA_CERTS` (нужен PEM), но с Госуслуг капитан скачал двоичные `.cer` → загрузчик `src/server/certs.ts` принимает DER и PEM и добавляет их через `tls.setDefaultCACertificates` (проверено тестом с самоподписанным HTTPS-сервером: до — DEPTH_ZERO_SELF_SIGNED_CERT, после — ok).

### D-021 — Правки по опросу студентов · Капитан (опрос, 07.11)
11 ответов (2 курс). Добавлен блок «Баллы по сегодняшним предметам» на «Сегодня»; изменения расписания и план по БРС сделаны главным. Подробно — `docs/research/SURVEY_RESULTS.md`.

### D-022 — Вложения хранятся в PostgreSQL (`bytea`) · ИИ (07.11)
На Amvera у контейнера нет постоянного диска для файлов, а внешнее S3-хранилище — лишний ключ и лишняя регистрация. Ограничения (5 МБ, 10 файлов на заявку) держат объём БД маленьким. Тип файла определяется по сигнатуре содержимого, а не по расширению. В реальном сервисе — объектное хранилище вуза и антивирусная проверка.

### D-023 — Пароль нельзя «показать», только сменить · ИИ по правке капитана №7 (07.11)
Правка «пароль под звёздочками в профиле» выполнена как строка «••••••••••» и форма смены. Показать сохранённый пароль невозможно и не нужно: в БД только argon2id-хэш. Смена требует текущий пароль, правила: ≥10 символов, буквы и цифры; после смены завершаются остальные сессии. Пароли опубликованных демо-аккаунтов менять нельзя (`DEMO_LOCKED_LOGINS`), иначе жюри не сможет войти.

### D-024 — Подтверждение для необратимых действий · Капитан (правка №6, 07.11)
Единый компонент `src/components/ui/confirm.tsx` (Radix AlertDialog): фокус на безопасной кнопке «Нет, оставить», Esc закрывает. Применён к отмене записи, отзыву и отклонению заявки, отмене пары и сбросу демо-данных.

### D-025 — Даты числами, а не днями недели · Капитан (раунд 2, 07.11)
«Во вторник» требует пересчёта в уме. Везде: «сегодня / завтра» или дата «17 ноября»; день недели — подписью ниже. Реализовано в `relativeDay()` и `nearDay()` (`src/lib/time.ts`).

### D-026 — Мягкий красный для отмен · Капитан (раунд 2, 07.11)
Сплошной красный оставлен только для счётчиков непрочитанного. Отмены — светлый фон `danger-bg`, рамка `danger-line`, красный текст: заметно, но не «кричит», контраст AA сохранён.

### D-027 — Даты: только полные месяцы · Капитан (раунд 3, 11.11)
Один формат во всём интерфейсе и текстах уведомлений: «16 ноября», при необходимости «16 ноября (пн)» и «13 ноября, 07:15». Источник — `fmt` в `src/lib/time.ts`; своих `Intl.DateTimeFormat` в компонентах нет.

### D-028 — Подсказки первого входа хранятся в браузере · ИИ (11.11)
Флаг «видел» — в `localStorage`, а не в БД: демо-аккаунты общие, и каждый проверяющий должен увидеть подсказки у себя. Без доступа к хранилищу подсказки просто не открываются сами.

### D-029 — Оценка работы деканата: одна на заявку, только закрытую · ИИ (11.11)
Таблица `request_feedback` (уникальный `request_id`, CHECK 1–5). Отозванную самим студентом заявку не оцениваем. Деканат видит среднюю за 30 дней по офису и по своим заявкам — для улучшения процесса, а не для «наказания».

### D-030 — «Выйти на других устройствах» отключено в демо-аккаунтах · ИИ (11.11)
Под общими логинами работают несколько проверяющих: кнопка разлогинила бы друг друга. Логика в `endOtherSessions()` проверена unit-тестом на обычном аккаунте.

### D-031 — Чат-боты: MAX — код готов «к подключению», Telegram — не делаем · Капитан (11.11)
Telegram в России в 2026 году ограничен, запросы к Bot API с российских серверов блокируются; работа через зарубежный релей — обход ограничений. Ботов MAX могут публиковать только юрлица, ИП и самозанятые после верификации — у студента ключа не будет. Решение: бот MAX пишется полностью и тестируется, но включается только при наличии ключа в переменных окружения.

### D-032 — Web Push на node:crypto, ключи VAPID в БД · ИИ (11.11)
Популярная библиотека `web-push` распространяется по MPL-2.0 (не «разрешительная» в строгом смысле правил конкурса), поэтому VAPID (RFC 8292) и шифрование aes128gcm (RFC 8291) реализованы в `src/server/push.ts` (~100 строк) и проверены тестом «со стороны браузера». Ключи создаются при первом запуске и лежат в `app_settings` — капитану не нужно заводить переменные; при желании их можно задать в env `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`.

### D-033 — Подписка на календарь по секретной ссылке, хэш в БД · ИИ (11.11)
Календарь телефона не умеет входить по паролю, поэтому доступ — по 192-битному токену в адресе. В БД — только SHA-256; ссылку показываем один раз, «новая ссылка» отзывает старую. Частоту обновления определяет приложение календаря (Apple/Яндекс ~1 ч, Google — до суток), поэтому срочные изменения дублируются уведомлениями.

### D-034 — Утренняя сводка: планировщик внутри приложения · ИИ (11.11)
Отдельного cron на Amvera не нужно: раз в 5 минут сервер проверяет, наступило ли 7:30 по Москве; отметка «отправлено за дату» ставится атомарно в БД, поэтому второй экземпляр сервера не продублирует рассылку. Отключается env `MORNING_DIGEST=off`.

### D-035 — Четыре языка интерфейса, без библиотеки i18n · Капитан (раунд 3), реализация ИИ (11.11)
Английский — первым (большинство иностранных студентов), затем китайский и французский. Собственный модуль (~120 строк) вместо next-intl: не нужна перестройка маршрутов под `/en/...`, язык — в cookie. Русский словарь — источник истины, TypeScript проверяет полноту переводов. Не переводятся: тексты людей (объявления, комментарии), официальный текст справки (документ выдаётся на русском; для иностранцев есть отдельная справка на английском), кабинет сотрудника. Китайский и французский — машинный перевод, нужна вычитка носителем.

### D-036 — Перевод содержимого из БД: словарь + шаблоны · Капитан (раунд 4), реализация ИИ (11.11)
Капитан попросил перевести всё, что видно на английской версии. Тексты деканата в реальной системе пишут люди, поэтому полноценно — это машинный перевод при публикации (или GigaChat). Для концепта: демо-тексты переведены заранее (словарь), системные сообщения переводятся по шаблонам с разбором дат и аудиторий; если перевода нет — показывается оригинал. Русская версия не меняется.

### D-037 — Заявление об оплате обучения · Капитан (раунд 4, 11.11)
Отдельный вид заявки для обучающихся по договору (рассрочка/отсрочка, материнский капитал, третье лицо, возврат переплаты), срок рассмотрения 10 рабочих дней, пункт 7.7 Положения. Без суммы и реквизитов — сумму фиксирует договор и финансовый отдел.

### D-038 — Панель руководителя: только агрегаты · ИИ (раунд 6, 11.11)
Показатели считаются SQL-запросами по заявкам, истории статусов и отзывам; «время обработки» — от подачи до первого итогового статуса («готова» или «отклонена»), «в срок» — не позже установленного срока. ФИО студентов на панели нет. Таблица методистов подписана: цифры — для распределения нагрузки, а не для оценки людей по одному показателю.

### D-039 — Раннее предупреждение = тот же расчёт, что у студента · ИИ (раунд 6, 11.11)
Риск считает та же функция `summarize()`, что показывает риск студенту, — чтобы деканат и студент видели одно и то же. Единственное действие — пригласить на консультацию (помощь, а не наказание). Повтор по той же дисциплине — не чаще раза в 7 дней, чтобы не превращать приглашения в давление.

### D-040 — ИИ-черновик ответа: минимум данных, человек решает · ИИ (раунд 6, 11.11)
Черновик только заполняет поле — отправляет методист. В GigaChat не передаются ФИО, зачётка и контакты; имя подставляется после ответа модели. Без ключа — шаблоны по статусам. Неизвестное модель помечает «[в квадратных скобках]», и сервер не принимает комментарий с такой пометкой — недописанный черновик не уйдёт студенту. Лимит — 30 черновиков в час на сотрудника.

### D-041 — Схема «Как пройти» — вымышленная · Капитан (раунд 6, 11.11)
Капитан выбрал вымышленный вариант. Корпуса, этажи и правило нумерации («первая цифра — этаж, вторая — блок») придуманы; на странице — пометка «Схема условная и вымышленная». Маршрут строит чистая функция `routeTo()` (unit-тест); в реальном запуске её заменила бы схема от хозяйственной службы.

### D-042 — Анонимный опрос: разделение «голос» и «ответ» · ИИ (раунд 6, 11.11)
Ответ хранится без studentId и без времени (только день). Повторное голосование блокирует отдельная таблица с `sha256(секрет:студент:курс)`; секрет — в `app_settings`, в браузер не попадает; связи между таблицами нет. Деканат видит итоги курса только при ≥ 3 ответах (k-анонимность), комментарии — тоже; студента просят не писать имён. Ограничение честно указано в SECURITY.md: администратор БД с секретом может узнать, *кто* голосовал, но не *как*.

### D-043 — Портфолио и резюме · ИИ (раунд 6, 11.11)
Студент добавляет записи сам; отметку «подтверждено деканатом» ставит только деканат (у новой записи она всегда выключена), подтверждённую запись студент удалить не может. Резюме — отдельная страница без оболочки кабинета, печать в PDF средствами браузера (без серверной генерации и новых зависимостей); «бумага» всегда светлая. Дисклеймер концепта есть и на печати.

### D-044 — Быстрые действия на главной · Капитан (раунд 7: «чтобы всё было интуитивно ясно»), реализация ИИ (11.11)
Замер путей показал: на телефоне «Заказать справку», «Неделя» и статус заявки лежали в 4 экранах прокрутки (≈ 8–11 с по KLM). Добавлена строка из 4 плиток сразу под карточкой пары и строка статуса активной заявки (только на телефоне). Плиток ровно 4: больше — и строка перестаёт быть «быстрой» (закон Хика), редкие задачи (резюме, сессия, опрос) остаются в меню.

### D-045 — Группы в меню · ИИ (раунд 7, 11.11)
11 пунктов одним списком → три группы «Учёба / Деканат / Моё» (у сотрудника — «Работа / Аналитика / Сервис»). «Как пройти» перенесён в «Учёбу», «Уведомления» — в «Деканат». Нижнее меню телефона не менялось (5 пунктов — оптимум), но «Ещё» теперь подсвечивается и на новых разделах.

### D-046 — «Посольство 2.0»: эволюция, а не смена стиля · Капитан (раунд 7)
Капитан выбрал «развить „Посольство“» и «умеренную» анимацию. Только CSS-токены и классы, без библиотек анимации; движение — `transform`/`opacity`, выключается системной настройкой «Уменьшить движение». Контраст и доступность перепроверены axe (WCAG 2 A/AA) на 20 страницах в обеих темах.

### D-047 — Порядок очереди деканата · ИИ (раунд 7, 11.11)
«Активные» сортируются: сначала требующие действия (подана / в работе / ждёт студента) по сроку, затем «Готовы к выдаче». Раньше сентябрьские готовые справки занимали верх списка, а просрочки были на 10-й и 13-й строках.
